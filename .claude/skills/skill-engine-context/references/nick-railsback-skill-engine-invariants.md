# nick-railsback/skill-engine — Reference invariants and the verify.sh gate

A contextualizer's file structure is not stylistic — the navigator's loading model and the engine's pre-approval validation both depend on predictable structure, so the artifact contract is treated as a spec that automated checks validate against. Source: [`02-artifact-contract.md`](https://github.com/nick-railsback/skill-engine/blob/b075dae1517b6f4f727547bd2303b0cf649adc64/plugin/skill-engine/docs/02-artifact-contract.md#L3-L5).

## The four reference invariants

The four framing invariants — first-5K, depth-1, max-100-line-TOC, and SHA-pin — are the load-bearing rules a corpus must satisfy. Not all are mechanically enforced: the shipped validator is the contextualizer-side `verify.sh` (eleven named checks), which backs depth-1 (inside the catalog-bijection check) directly, while SHA-pin is enforced separately by the Check-7 `permalink_density.py` CI lint, and first-5K and the TOC rule are specified authoring discipline the reviewer backstops. Source: [`05-invariants.md` banner](https://github.com/nick-railsback/skill-engine/blob/b075dae1517b6f4f727547bd2303b0cf649adc64/plugin/skill-engine/docs/05-invariants.md#L32-L32).

**first-5K** — a navigator's *standing instructions* (invariants, critical rules, dispatch logic) must fit in the first 5K bytes of `SKILL.md` body, frontmatter excluded. The platform constraint is auto-compaction: when the orchestrator re-attaches skills mid-conversation the budget for all attached skills is ~25K bytes, so reserving 5K per navigator leaves multi-skill headroom, and a navigator that exceeds the cap is silently truncated. Source: [`05-invariants.md` Invariant 8](https://github.com/nick-railsback/skill-engine/blob/b075dae1517b6f4f727547bd2303b0cf649adc64/plugin/skill-engine/docs/05-invariants.md#L454-L460).

The `## Catalog` table is exempt from the budget under the catalog-as-TOC carve-out — it is a router, not standing instructions — so multi-domain navigators with large sectioned catalogs are not penalized. Source: [`02-artifact-contract.md` § Navigator size budget](https://github.com/nick-railsback/skill-engine/blob/b075dae1517b6f4f727547bd2303b0cf649adc64/plugin/skill-engine/docs/02-artifact-contract.md#L361-L369).

**depth-1** — from `SKILL.md`, every reference resolves to a single load target one link deep: either a flat `references/<slug>.md` (file form) or a `references/<slug>/` directory whose canonical primary `.md` shares the directory's basename (directory form). No further delegation to a sub-directory; the primary IS the reference body. The failure mode it prevents is shallow probes — nested references tempt a `head -100` preview instead of a full read. Source: [`05-invariants.md` Invariant 9](https://github.com/nick-railsback/skill-engine/blob/b075dae1517b6f4f727547bd2303b0cf649adc64/plugin/skill-engine/docs/05-invariants.md#L462-L470).

Depth-1 is the one framing invariant `verify.sh` enforces mechanically — but inside the `catalog-bijection` check, which rejects any catalog row whose target encodes a nested path (depth ≥ 3, or a depth-2 `.md` whose basename does not match its parent directory, or any sub-directory), rather than as a standalone `max-ref-depth` check. Source: [`02-artifact-contract.md` § Reference depth](https://github.com/nick-railsback/skill-engine/blob/b075dae1517b6f4f727547bd2303b0cf649adc64/plugin/skill-engine/docs/02-artifact-contract.md#L501-L507).

**max-100-line-TOC** — any reference body exceeding 100 lines must carry a Markdown TOC marker (typically `## Contents`) within its first 30 lines, so the model lands where it needs to instead of reading top-to-bottom; references under 100 lines are short enough to scan and need none. This is authoring discipline: there is no `long-ref-toc` check in the shipped `verify.sh`, so the reviewer backstops it. Source: [`05-invariants.md` Invariant 10](https://github.com/nick-railsback/skill-engine/blob/b075dae1517b6f4f727547bd2303b0cf649adc64/plugin/skill-engine/docs/05-invariants.md#L472-L478).

**SHA-pin** — the canonical pointer in a primary reference is a commit-SHA permalink with a line range, in the grammar of the source's own forge (on github.com, `https://github.com/<owner>/<repo>/blob/<sha>/<path>#L<start>-L<end>`; four more grammars are credited — GitHub Enterprise Server on any hostname, GitLab, Bitbucket Server, Bitbucket Cloud, Azure DevOps, hostnames drawn from the contextualizer's own `research/source-paths.json` plus github.com always accepted), where `<sha>` is a 40-char commit SHA captured at harvest time; stable version tags (`v1.2.3`) are accepted equivalently as immutable, but only on github.com. The failure mode it prevents is link rot — branch-pinned URLs on `blob/main/...` survive only while the file stays at that path on the default branch (industry rot estimates run 38–66% over one-to-two years). Source: [`02-artifact-contract.md` § SHA-pinned permalinks](https://github.com/nick-railsback/skill-engine/blob/b075dae1517b6f4f727547bd2303b0cf649adc64/plugin/skill-engine/docs/02-artifact-contract.md#L594-L616).

SHA-pinning is enforced not by `verify.sh` but by the Check-7 `permalink_density.py` CI lint, which scans the references corpus only — navigator prose, chapter prose, and READMEs may carry unpinned "intentional latest" URLs (e.g. a project README or stable spec page) without flagging. Source: [`02-artifact-contract.md` § When to keep an unpinned URL](https://github.com/nick-railsback/skill-engine/blob/b075dae1517b6f4f727547bd2303b0cf649adc64/plugin/skill-engine/docs/02-artifact-contract.md#L620-L628).

## The paragraph→permalink density rule (SELF-AUDIT Check 7)

The corpus-wide density rule is the honesty floor behind SHA-pin: across `references/**/*.md`, at least 80% of prose paragraphs must carry a SHA-pinned (or, on github.com, stable-tag-pinned) permalink in the source forge's grammar within 5 lines. The navigator is out of scope (a router), companion files participate on equal footing, and the aggregate — total covered paragraphs over total in-scope paragraphs — is the pass/fail gate; per-file numbers are diagnostic only. Source: [`self-audit/references/check-7-permalink-density.md` § Check 7](https://github.com/nick-railsback/skill-engine/blob/b075dae1517b6f4f727547bd2303b0cf649adc64/plugin/skill-engine/skills/self-audit/references/check-7-permalink-density.md#L5-L27).

A *prose paragraph* is a maximal run of non-blank lines that is not a heading, fenced code block, table row, list item, blockquote, HTML comment, or frontmatter; a *permalink* is a SHA-pinned (or, on github.com, stable-tag-pinned) URL in the source forge's own grammar — the five grammars the lint credits are enumerated in the artifact contract's canonical-form section, not restated here. The 80% bar makes the structural-honesty disclaimer — *"where a paragraph lacks a nearby permalink, treat the claim as unverified"* — mechanically true rather than aspirational. Source: [`self-audit/references/check-7-permalink-density.md` § What counts](https://github.com/nick-railsback/skill-engine/blob/b075dae1517b6f4f727547bd2303b0cf649adc64/plugin/skill-engine/skills/self-audit/references/check-7-permalink-density.md#L29-L40).

## The eleven verify.sh named checks

`verify.sh` audits only the contextualizer it sits in — engine-repo invariants (doctrine greps, template/example sync, version parity) are audited separately by `plugin/skill-engine/tests/doctrine.sh`. Its tool surface is bash + jq + POSIX utilities with no third-party dependencies, and the run summary (not the header comment) is the authoritative list of what ran. Source: [`verify.sh` header](https://github.com/nick-railsback/skill-engine/blob/b075dae1517b6f4f727547bd2303b0cf649adc64/plugin/skill-engine/engine-bootstrap-templates/verify.sh#L9-L40).

|---|---|---|
| `source-paths-shape` | `research/source-paths.json` parses as JSON with integer `schema_version: 1` and a `sources[]` array | [L260-L279](https://github.com/nick-railsback/skill-engine/blob/b075dae1517b6f4f727547bd2303b0cf649adc64/plugin/skill-engine/engine-bootstrap-templates/verify.sh#L260-L279) |
| `source-entries` | each `sources[]` entry has required fields (`id`, `kind`, `status`, `lifecycle.state`, url-or-path) and valid enums; web-doc `crawl_mode`/`page_list`/`crawl_budget` rules | [L281-L553](https://github.com/nick-railsback/skill-engine/blob/b075dae1517b6f4f727547bd2303b0cf649adc64/plugin/skill-engine/engine-bootstrap-templates/verify.sh#L281-L553) |

| `skill-json-trijection` | when `SKILL.json` is present, 3-way correspondence between catalog rows, non-draft JSON entries, and reference files; silent-skip otherwise | [L1648-L1778](https://github.com/nick-railsback/skill-engine/blob/b075dae1517b6f4f727547bd2303b0cf649adc64/plugin/skill-engine/engine-bootstrap-templates/verify.sh#L1648-L1778) |

The first five are the invariant-backing structural checks; `web-doc-snapshot-present`, `monorepo-coverage`, `companions-coverage`, and `catalog-density` are advisory heuristics that surface reviewer concerns, and `skill-json-trijection` is conditional on the optional machine-readable sibling. Many checks skip-with-pass (`[N/A]`) in clean empty states — `sources: []`, an absent `references/`, or a fresh bootstrap between scaffold and first DISCOVER emit — rather than failing. Source: [`verify.sh` skip cases](https://github.com/nick-railsback/skill-engine/blob/b075dae1517b6f4f727547bd2303b0cf649adc64/plugin/skill-engine/engine-bootstrap-templates/verify.sh#L29-L38).

Four verdict semantics govern the counters: `pass` and `skip` both increment `passed` (`[N/A]` is a pass, not a failure, and every N/A prints its one-line reason); `fail` increments `failed` and prints `[FAIL]`; `warn` prints `[WARN]` to stderr and increments neither counter, so heuristic warnings never fail the gate. Source: [`verify.sh` verdict functions](https://github.com/nick-railsback/skill-engine/blob/b075dae1517b6f4f727547bd2303b0cf649adc64/plugin/skill-engine/engine-bootstrap-templates/verify.sh#L68-L85).

The run exits 1 whenever `failed` is non-zero and 0 otherwise, so a proposal with any `[FAIL]` aborts the staged write and the user never sees a broken proposal. Source: [`verify.sh` summary](https://github.com/nick-railsback/skill-engine/blob/b075dae1517b6f4f727547bd2303b0cf649adc64/plugin/skill-engine/engine-bootstrap-templates/verify.sh#L1783-L1790).
