# skill-engine — DISCOVER and REFRESH: the content pipelines and the staging gate

DISCOVER and REFRESH are the engine's two content-generating pipelines. DISCOVER writes new reference files for the parts of a source that matter; REFRESH re-checks existing references against current upstream and re-stamps drift. Neither writes to the live contextualizer directly: both stage every write into a sibling `<slug>-context.proposed/` directory that three gate commands (review, apply, discard) promote or throw away. This reference curates the model both pipelines share — the goal-given posture, the in-scope filter, the clone cache, and the staging model — and points at the source for the mechanical detail. Source: [`08-discover-pipeline.md` L3-L10](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/docs/08-discover-pipeline.md#L3-L10).

For the four reference invariants, the `source-paths.json` schema, and the reference shape these pipelines emit, see artifact-contract; for the machine checks that gate output, see invariants; for how a run is routed and reviewed end to end, see workflows; for the design commitments (consent-gated, file-based, no daemons) that shape both pipelines, see principles.

## Goal-given posture

When `/skill-engine:discover` runs, the engine hands the model a goal, not a procedure: "discover the essence of the registered sources, write reference files for the parts that matter, satisfy the four reference invariants, use any procedural reasoning you find appropriate." There is deliberately no fixed Stage 0/1/2 worker dispatch, no keystroke menu, no prescribed importance-scan or commodity-filter rules — the model varies its approach by what the corpus rewards. Source: [`08-discover-pipeline.md` L12-L25](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/docs/08-discover-pipeline.md#L12-L25).

`verify.sh`, the permalink-density lint, and the reviewer are the trust mechanism, not a rigid pipeline. Two sessions on the same corpus may produce different reference counts, different topical partitions, and different prose styles — variance below the invariant floor is acceptable and expected, because the invariants plus the named checks are what bind quality. Source: [`discover/SKILL.md` L64-L69](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/discover/SKILL.md#L64-L69).

## Output contract

DISCOVER's output is two load-bearing things. First, reference files in `references/`, each citing its source by path plus content-hash and each satisfying the four invariants (first-5K, depth-1, max-100-line-TOC, SHA-pin). Second, a post-run summary for the author. Source: [`discover/SKILL.md` L45-L62](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/discover/SKILL.md#L45-L62).

The post-run summary is paragraph-form (≤30 lines typical) with five components: a coverage report (what was read, what the references emit, cited by path+content-hash), skip-reasoning (files and companions considered but excluded, empty case allowed), proposed companions (one line each, with rationale and the accept path), a creative-input "rerun with hint" gesture, and a staging-dir handoff line naming the proposed directory and the three review/apply/discard commands. Source: [`discover/references/proposal-and-post-run.md` L134-L222](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/discover/references/proposal-and-post-run.md#L134-L222).

Every prose paragraph in an emitted reference must carry a SHA-pinned permalink, in the source forge's grammar, within 5 lines; unpinned `blob/main/...` URLs do not satisfy the requirement, and SELF-AUDIT Check 7 enforces ≥80% paragraph→permalink coverage corpus-wide. This makes the structural-honesty claim mechanically true: a paragraph without a nearby permalink is unverified curation. Source: [`08-discover-pipeline.md` L58-L72](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/docs/08-discover-pipeline.md#L58-L72).

## In-scope rules

Both pipelines filter `source-paths.json` to an in-scope set before reading anything. A source is in-scope when `archived: false` (or absent — defaults false), `lifecycle.state ∈ {reachable, unknown}` (`removed` is skipped; `moved` surfaces for user accept but is not crawled until its URL is updated), and `status ∈ {intake, proposed, confirmed}` (`rejected` companions are skipped). Source: [`discover/references/cache-and-clone.md` L46-L51](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/discover/references/cache-and-clone.md#L46-L51).

A positional argument that matches a registered source id narrows scope to that one source (an unmatched id renders an error listing the registered ids and exits); a `--hint='<hint>'` argument is passed through as authoritative author input that shapes discovery emphasis for the session. Source: [`discover/references/cache-and-clone.md` L53-L62](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/discover/references/cache-and-clone.md#L53-L62).

An idempotency no-op gate prevents churn: before re-reading any source, the pipeline checks `research/.discover-cache.json` against current upstream SHAs, and if every in-scope source's SHA is unchanged since its last cache entry AND no `--hint` was supplied this run, it summarizes "no work to do" and exits cleanly. A hint always overrides the gate — it signals the author wants a re-look at fixed inputs. Source: [`discover/references/cache-and-clone.md` L64-L71](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/discover/references/cache-and-clone.md#L64-L71).

## Reading sources

For `kind: git-managed` sources the model prefers the `gh` and `git` CLIs — `gh repo view`, `gh api repos/<owner>/<repo>/contents/<path>?ref=<ref>`, `git ls-tree --recursive <ref>`, `git show <ref>:<path>` — over WebFetch, which returns rendered HTML that costs roughly 10× more tokens to parse. WebFetch is reserved for `kind: external-doc` or for git sources where CLI access fails. Source: [`discover/references/cache-and-clone.md` L344-L360](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/discover/references/cache-and-clone.md#L344-L360).

The `<ref>` token resolves branch-else-HEAD: if the `source-paths.json` entry carries a `branch` field, that branch is the ref; otherwise the ref is `HEAD`. Reference SHAs cite the resolved commit on the tracked ref, not the repo-wide default — a contextualizer monitoring a `dev` branch never quietly references main-branch commits. Source: [`08-discover-pipeline.md` L138-L143](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/docs/08-discover-pipeline.md#L138-L143).

## The local clone cache

For large git-managed sources the engine offers a local clone under the XDG convention `~/.cache/skill-engine/git-managed/<source_id>-<sha>/`; web-doc snapshots land in a parallel `~/.cache/skill-engine/web-doc/<source_id>-<crawl_id>/`. The cache persists across runs, is independent of the proposed-dir model (it holds upstream sources, not contextualizer-internal writes), and is advanced in place by REFRESH on a SHA advance rather than re-cloned: REFRESH fetches the new commit into the existing directory and keeps both the old and new commit reachable there, which is what makes the set of paths that changed between them computable offline, then renames the directory to the new SHA and removes any now-superseded sibling. Source: [`09-discover-config.md` L120-L145](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/docs/09-discover-config.md#L120-L145) for the cache location and the consent model, [`refresh/references/tool-and-output-mechanics.md` § Cache garbage collection](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/refresh/references/tool-and-output-mechanics.md#L72-L133) for the in-place advance.

The engine never clones without consent. DISCOVER pre-flight step 6 probes the kind-appropriate cache directory (git-managed enumerates every `<source_id>-*` sibling and requires both an exact `<source_id>-<resolved_sha>` name and an actual `.git/` subdirectory, so a stale-SHA directory and a half-written one are both misses regardless of the order the filesystem lists them in; web-doc treats any directory match as a hit) and, on a miss, prompts the user once per source with kind-aware wording. `y`/`yes` is consent; `N`, blank, or anything else declines, and a decline is sticky for the session. Two mutually exclusive flags answer the whole git-managed branch in one gesture instead of once per source — `--clone-all` consents for every in-scope git-managed source, `--clone-none` sets the sticky decline for all of them — and neither touches the web-doc branch, which keeps prompting. Source: [`discover/references/cache-and-clone.md` L73-L179](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/discover/references/cache-and-clone.md#L73-L179).

On git-managed consent the skill clones through `bin/cache-git.sh`, the one helper that now owns every cache-mutating git call the shipped recipes make, using an atomic-rename idiom: it refuses an unsafe `source_id`, resolves the SHA with `git ls-remote`, clones `--depth=1 --filter=blob:none` into a `<dest>.tmp.$$/` scratch path, and `mv`s it to the canonical `<source_id>-<sha>` name only on success — guarded so a rename onto an existing destination cannot nest a re-clone inside the warm cache — so an interrupted clone never leaves a half-written directory at the lookup path. A source carrying `files_of_interest` takes the parallel `sparse-clone` subcommand instead. A clone failure emits one fallback line and proceeds with the CLI path — it does not abort DISCOVER. Source: [`discover/references/cache-and-clone.md` L180-L227](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/discover/references/cache-and-clone.md#L180-L227), [`plugin/skill-engine/bin/cache-git.sh`](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/bin/cache-git.sh#L1-L33).

## The staging model

Every write from DISCOVER or REFRESH goes to `$CTX_PROPOSED` — a sibling `<slug>-context.proposed/` directory that mirrors the live contextualizer — never to `$CTX_ROOT`. Reads (the drift baseline) still come from the live tree; the live skill is untouched until `/skill-engine:apply <name>` promotes the proposal. The one exception is the upstream-source clone cache, which lands in the user-level cache root regardless. Source: [`discover/references/staging-and-contextualizer-model.md` L29-L40](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/discover/references/staging-and-contextualizer-model.md#L29-L40).

The proposed dir is copy-on-write and sparse. On a first run (empty live `references/`) it is created from scratch with the full generated set. On a REFRESH-against-existing or incremental DISCOVER, only files this run regenerates are written under `$CTX_PROPOSED/`; files left untouched are not copied, and the manifest records them as `unchanged` so apply leaves the corresponding live files alone. Source: [`discover/references/staging-and-contextualizer-model.md` L44-L66](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/discover/references/staging-and-contextualizer-model.md#L44-L66).

## The manifest

At end of run the pipeline writes `$CTX_PROPOSED/.review/manifest.json` with `schema_version: 1` and one entry per contextualizer file. Each entry carries a `path`, a `status` of `added` / `modified` / `removed` / `unchanged`, and `sha_before` / `sha_after` content-hashes, with a pinned null-field convention: `added` ⇒ `sha_before: null`; `removed` ⇒ `sha_after: null`; `unchanged` ⇒ both shas populated and equal. Source: [`discover/references/staging-and-contextualizer-model.md` L68-L82](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/discover/references/staging-and-contextualizer-model.md#L68-L82).

```json
{
  "schema_version": 1,
  "entries": [
    { "path": "references/foo.md", "status": "added",    "sha_before": null,      "sha_after": "abc1234" },
    { "path": "references/bar.md", "status": "modified", "sha_before": "def5678", "sha_after": "9abc012" },
    { "path": "references/baz.md", "status": "removed",  "sha_before": "11112222","sha_after": null },
    { "path": "research/source-paths.json", "status": "unchanged", "sha_before": "33334444", "sha_after": "33334444" }
  ]
}
```

Removed-detection is deterministic, not agent-recall: when finalizing the manifest the pipeline enumerates the live `references/` baseline and records any live reference the proposed navigator's catalog no longer cites as `removed` (`sha_before` = the live file's hash, `sha_after: null`), even when this run never wrote to the proposed tree for that path. Without this diff, a regeneration that simply stops emitting a reference would leave an orphaned live file behind until it surfaced later as a catalog↔references bijection failure. Source: [`discover/references/staging-and-contextualizer-model.md` L84](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/discover/references/staging-and-contextualizer-model.md#L84).

The run also stamps `REVIEW.md.template` into `$CTX_PROPOSED/.review/REVIEW.md` (one substitution: the `<name>` token becomes the slug without `-context`) so the author has the predict-then-compare scaffold to fill. Three commands then gate promotion: `/skill-engine:review <name>` inspects the manifest and opens `REVIEW.md`, `/skill-engine:apply <name>` promotes the proposed dir to live, and `/skill-engine:discard <name>` removes it without promoting — with the user signing off in `REVIEW.md` Step 3 before apply will run. Source: [`discover/references/staging-and-contextualizer-model.md` L86-L88](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/discover/references/staging-and-contextualizer-model.md#L86-L88).

Because the proposed tree is sparse, `verify.sh` is not run against it directly — running it against a partial tree would fail presence checks or N/A-skip the bijection. Instead the pipeline builds an ephemeral merged tree (`cp -R` the live baseline, overlay the proposed changes, apply the manifest's `removed` deletions, strip `.review/`), confirms `verify.sh` exits 0 against that merge — exactly what apply would produce — then writes the manifest. A non-zero exit aborts the proposed-dir write, so the user never sees a `REVIEW.md` for a broken proposal. Source: [`discover/references/proposal-and-post-run.md` L67-L132](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/discover/references/proposal-and-post-run.md#L67-L132).

## The proposal threshold

The default is propose, not exclude. When a candidate companion source is plausibly in-domain it belongs in the summary's **Proposed companions**, not Skip-reasoning — the user's `status: "proposed" → confirmed/rejected` gate is the filter, and pre-filtering by agent judgment silently narrows the catalog without the user ever seeing the call. Skip-reasoning is reserved for clear non-fits: off-domain repos, unrelated forks, accidental name collisions, archived/abandoned candidates. Source: [`discover/SKILL.md` L108-L121](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/discover/SKILL.md#L108-L121).

Same-domain different-language ports are the named exception: they are still proposed (never skipped), but with a verbatim `recommend: reject` rationale, because the navigator's `description` field drives invocation and a mixed-in port makes queries about the ported language fire the wrong skill. Docs repos and higher-level packages layered on the core are not ports — they carry distinct signal and are proposed by default; the user makes the call either way. Source: [`discover/references/proposal-and-post-run.md` L5-L19](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/discover/references/proposal-and-post-run.md#L5-L19).

## Lifecycle handling

For each in-scope source the pipeline decides whether upstream is still `reachable`, `moved`, `removed`, or `unknown`, and writes transitions to `$CTX_PROPOSED/research/source-paths.json` (seeded copy-on-write from the live file, recorded as `modified` in the manifest) rather than mutating the live tree — the transitions are part of the proposal the user reviews, and promoting them silently before review would defeat the staging model. Source: [`discover/references/cache-and-clone.md` L415-L441](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/discover/references/cache-and-clone.md#L415-L441).

When a transition would affect an existing reference or the navigator (a `moved` URL is cited; a `removed` source is referenced) the pipeline emits a lifecycle sweep dry-run per the delivery doctrine, guarded by proposal-token and per-file SHA integrity gates. The conservative default is load-bearing: any non-zero probe exit maps to `unknown`, never `removed`, because `removed` permanently drops a source from refresh scope — and DISCOVER never flips `archived` itself — the user sets it, or REFRESH's Phase 0.5 forge probe stages it for the reviewer. Source: [`discover/references/cache-and-clone.md` L442-L449](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/discover/references/cache-and-clone.md#L442-L449).

## REFRESH

REFRESH shares DISCOVER's goal-given posture and staging model but has a narrower job: it brings the contextualizer's existing references into agreement with current upstream state — probing lifecycle, detecting content drift by per-source SHA, and re-emitting the references that moved. It does not propose new sources or expand coverage (that is DISCOVER's domain) and does not parse lockfiles or query registries. Source: [`refresh/SKILL.md` L6-L14](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/refresh/SKILL.md#L6-L14).

REFRESH's phases run in order, each feeding the next: Phase 0.5, a forge-dispatched archive check on every in-scope git-managed source; Phase 1, a kind-dispatched HEAD probe (`git ls-remote` for git-managed, HTTP HEAD for web-doc, where only 404/410 — the statuses that assert the resource is gone — map to `removed` while an auth wall or rate limit maps to `unknown`); Phase 2, a web-doc decay check; Phase 3, a re-crawl-and-diff apply pass; and Phase 4, a web-doc cache-GC pass. The half-numbered first phase is the seam where v0.9.0 added archival detection ahead of a probe order that was already fixed. Source: [`refresh/references/drift-detection-and-phases.md` § Phases](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/refresh/references/drift-detection-and-phases.md#L206-L453), [`refresh/SKILL.md` L81-L83](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/refresh/SKILL.md#L81-L83), [`refresh/references/drift-detection-and-phases.md` L3](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/refresh/references/drift-detection-and-phases.md#L3-L3).

On a git-managed source whose SHA advanced, REFRESH scopes what it re-reads instead of re-reading the corpus. The in-place cache advance leaves the old and new commit in one directory, so the changed-path set between them is computed locally and written to `research/.discover-inventory.json`; `cited_paths.py --changed` then intersects that set against each reference's cited paths and prints a re-emit candidate set plus the uncited changes — the changed paths no reference covers. REFRESH re-reads the candidates and states a reason in the post-run summary for any non-candidate it re-emits anyway. With no inventory, or no source's `since_last_check`, there is no changed-path signal and the step is skipped rather than guessed at. This is what keeps a REFRESH proportional to how much upstream moved rather than to how large the source is. Source: [`refresh/references/drift-detection-and-phases.md` § Re-read scoping](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/refresh/references/drift-detection-and-phases.md#L360-L379), [`refresh/references/tool-and-output-mechanics.md` § the advance recipe](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/refresh/references/tool-and-output-mechanics.md#L72-L133).

REFRESH's idempotency gate is stricter than DISCOVER's — beyond unchanged upstream SHAs and no hint, it also requires that every source still holds `lifecycle.state ∈ {reachable, unknown}` since last run — and a `--lifecycle-only` flag runs just the lifecycle state-check pass, skipping drift detection and reference re-emit. Source: [`refresh/references/drift-detection-and-phases.md` L148-L170](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/refresh/references/drift-detection-and-phases.md#L148-L170).

REFRESH (and DISCOVER) also re-stamp `verify.sh` when it drifts from the engine template. The pipeline compares the live `verify.sh` against `$CLAUDE_PLUGIN_ROOT/engine-bootstrap-templates/verify.sh` by byte-for-byte SHA-256 equality and dispatches three cases: engine template unreachable → silent N/A in the coverage report; live `verify.sh` absent → manifest `added`; SHAs differ → manifest `modified`. Every re-stamp is written to `$CTX_PROPOSED/verify.sh` and surfaced in the `REVIEW.md` disagreement set — REFRESH MUST NOT write directly to the live `$CTX_ROOT/verify.sh` under any code path. Source: [`refresh/references/drift-detection-and-phases.md` L76-L130](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/refresh/references/drift-detection-and-phases.md#L76-L130).

Lifecycle transitions in REFRESH follow the same conservative model as DISCOVER — a non-zero probe ⇒ `unknown`, and an `archived: true` that Phase 0.5 detected is staged for the reviewer rather than written live — and a transition that touches a cited reference emits the same lifecycle sweep dry-run through the staging gate; the engine never auto-mutates references on a lifecycle change. The whole lifecycle pass is cheap (sub-second for typical 5–30 source contextualizers) and catches dead-link drift that accumulates silently, which is why weekly is the typical REFRESH rhythm. Source: [`refresh/references/drift-detection-and-phases.md` L184-L204](https://github.com/nick-railsback/skill-engine/blob/f772c0d95d409ed0a85e93f0b8a4b31bbb329d9a/plugin/skill-engine/skills/refresh/references/drift-detection-and-phases.md#L184-L204).
