# skill-engine: Design principles and doctrine

This reference distills the engine's design philosophy — why the pattern takes the shape it does and which stances are load-bearing enough that undoing them changes what the engine fundamentally is. It draws on the principles chapter and the doctrine log; for the reference and navigator shapes these principles produce see artifact-contract, for the checks that enforce them see invariants, and for the discovery/refresh runs that apply them see discover-refresh.

## Progressive disclosure: a small navigator over on-demand references

The pattern is one navigator skill (`<area-domain>-context`) plus on-demand reference files plus a manually-triggered engine — deliberately not twenty per-topic skills, not one mega-skill, and not a cron job. The navigator pays only ~100 tokens of always-on metadata; the reference bodies load only when a query pulls them, which maps onto Anthropic's Level 1 metadata / Level 2 SKILL.md body / Level 3+ bundled references framing ([`plugin/skill-engine/docs/01-principles.md`](https://github.com/nick-railsback/skill-engine/blob/711e3144e1ad81b50414667b9b5e3c0363989955/plugin/skill-engine/docs/01-principles.md#L6-L7)).

The pattern splits into two tiers: a domain-agnostic engine (navigator, discovery pipeline, release doctrine, templates) and a per-domain contextualizer (the reference content, source paths, catalog rows) that fits inside it. The engine ships once, the same shape, regardless of what is being documented; it has no opinion about what a contextualizer covers, only about how its content is shaped and maintained ([`plugin/skill-engine/docs/01-principles.md`](https://github.com/nick-railsback/skill-engine/blob/711e3144e1ad81b50414667b9b5e3c0363989955/plugin/skill-engine/docs/01-principles.md#L111-L113)).

## Goal-given delegation, not a fixed pipeline

The engine hands the model a task — "discover the essence; write references; satisfy invariants" — and validates the output via deterministic checks. It does not prescribe a fixed pipeline of stages, scoring rubrics, or worker dispatch; the model decides how to spend its context, what to read and skip and propose, within the bounds the task sets ([`plugin/skill-engine/docs/01-principles.md`](https://github.com/nick-railsback/skill-engine/blob/711e3144e1ad81b50414667b9b5e3c0363989955/plugin/skill-engine/docs/01-principles.md#L11-L13)).

The leverage lives in the contract, not the recipe: each workflow is framed as a task plus the invariants `verify.sh` will check, and the instinct to pre-script the steps between task and output is one to resist ([`plugin/skill-engine/docs/01-principles.md`](https://github.com/nick-railsback/skill-engine/blob/711e3144e1ad81b50414667b9b5e3c0363989955/plugin/skill-engine/docs/01-principles.md#L24-L24)).

The doctrine records this as a deliberate reversal. Discovery originally followed a prescribed multi-stage worker pipeline; it was retired because every stage carried scaffolding the engine had to maintain and the prescriptions got harder to keep coherent as the model improved. Discovery now hands the model the task and validates the output, not the path — the forward move was to get out of the way, not to add instrumentation ([`plugin/skill-engine/docs/doctrine.md`](https://github.com/nick-railsback/skill-engine/blob/711e3144e1ad81b50414667b9b5e3c0363989955/plugin/skill-engine/docs/doctrine.md#L41-L46)). See discover-refresh for how that plays out per run.

## Curation over re-specifying upstream

The engine curates the essence — reference files for the parts that matter — rather than re-transcribing upstream in full; artifact-contract governs the shape that curation must take. Sources stay deliberately thin: each is identified by its content-hash and citations resolve by file path and content-hash, and a tempting chunk-level granularity layer was rejected because it would multiply the persisted-state schema to solve a problem the engine does not have — most contextualizers are tens of sources, not thousands, so cold-cache refresh runs in seconds and costs cents ([`plugin/skill-engine/docs/doctrine.md`](https://github.com/nick-railsback/skill-engine/blob/711e3144e1ad81b50414667b9b5e3c0363989955/plugin/skill-engine/docs/doctrine.md#L49-L63)).

## Source materialization is consent-gated

The engine does not crawl or fetch content on its own initiative. Its cache lifecycle moves through four named, consent-gated stages: seed (the plugin asks before cloning anything), garbage-collect on refresh, a read-only status surface, and an opt-in `clean-cache` that dry-runs by default and needs a literal `yes` to delete — small stages in sequence, none of them automation the user did not ask for ([`plugin/skill-engine/docs/doctrine.md`](https://github.com/nick-railsback/skill-engine/blob/711e3144e1ad81b50414667b9b5e3c0363989955/plugin/skill-engine/docs/doctrine.md#L24-L30)). Once a source is materialized the engine clones it once and reads from the local checkout with filesystem tools rather than round-tripping a retrieval API per file ([`plugin/skill-engine/docs/01-principles.md`](https://github.com/nick-railsback/skill-engine/blob/711e3144e1ad81b50414667b9b5e3c0363989955/plugin/skill-engine/docs/01-principles.md#L37-L37)).

## Treat crawled content as data, not instructions

Untrusted upstream content is the risk that most defines the engine: its whole purpose is to ingest a README or a docs page and make it Claude's source of truth, which is exactly the setup a prompt-injection attacker wants — text an assistant will later read and may act on. The engine ships no injection scanner (no static analysis reliably detects adversarial natural language), so the only control is the reviewer-in-the-loop, and a proposal from an upstream you do not control deserves the scrutiny you would give a pull request from a stranger: read the diff, not the summary ([`SECURITY.md`](https://github.com/nick-railsback/skill-engine/blob/711e3144e1ad81b50414667b9b5e3c0363989955/SECURITY.md#L28-L34)).

## The trust model: what binds quality

Named `verify.sh` checks bind the mechanical floor. Before any diff is surfaced the engine runs pre-approval validation — frontmatter discipline, catalog↔reference bijection, and an end-to-end `verify.sh` pass — and a failed check blocks the diff and prompts a fix first, making "engine proposed bad output" a fail-closed condition rather than a fail-to-the-human one ([`plugin/skill-engine/docs/01-principles.md`](https://github.com/nick-railsback/skill-engine/blob/711e3144e1ad81b50414667b9b5e3c0363989955/plugin/skill-engine/docs/01-principles.md#L85-L91)).

The human reviewer binds the judgment floor. The engine never auto-applies changes; it surfaces the diff for approve/reject because a contextualizer's contents are an AI assistant's ground truth for an entire domain, and a wrong crawl silently propagating to every consumer is a worse failure than a five-minute review ([`plugin/skill-engine/docs/01-principles.md`](https://github.com/nick-railsback/skill-engine/blob/711e3144e1ad81b50414667b9b5e3c0363989955/plugin/skill-engine/docs/01-principles.md#L74-L74)).

Grounding density is the third leg. SHA-pinned permalinks on load-bearing claims are measured by the Check-7 `permalink_density.py` CI lint — a target of the reference-invariants framing, enforced separately from `verify.sh` — so citation coverage is checked rather than assumed; see invariants for the full list of what ships enforced versus specified ([`plugin/skill-engine/docs/05-invariants.md`](https://github.com/nick-railsback/skill-engine/blob/711e3144e1ad81b50414667b9b5e3c0363989955/plugin/skill-engine/docs/05-invariants.md#L32-L32)).

What these do not bind is determinism, and that is intentional. Because the engine validates the output and not the path, two runs over the same inputs may differ in shape; that variance is expected and acceptable as long as the contract holds ([`plugin/skill-engine/docs/doctrine.md`](https://github.com/nick-railsback/skill-engine/blob/711e3144e1ad81b50414667b9b5e3c0363989955/plugin/skill-engine/docs/doctrine.md#L43-L46)).

## Why the constellation holds together

Each principle is mundane alone; together they form a self-reinforcing pattern — frontmatter discipline keeps distribution working across platforms, goal-given delegation keeps the maintenance cost of a 30-reference contextualizer linear rather than exponential, token efficiency keeps cycles cheap, approval gates keep content trustworthy, and pre-approval validation catches the mistakes the reviewer would not notice. Pull any one out and the pattern degrades sharply ([`plugin/skill-engine/docs/01-principles.md`](https://github.com/nick-railsback/skill-engine/blob/711e3144e1ad81b50414667b9b5e3c0363989955/plugin/skill-engine/docs/01-principles.md#L193-L205)).
