# The skill-engine slash commands and the review to apply gate

The plugin ships twelve skills invokable as `/skill-engine:<skill>`: the router (`using-skill-engine`), the scaffolder (`engine-bootstrap`), five maintenance workflows (`discover`, `refresh`, `new-reference`, `status`, `self-audit`), the four review-workflow skills (`review`, `apply`, `discard`, `config-set`), and `clean-cache`. ([`03-engine.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/docs/03-engine.md#L20-L23), [`using-skill-engine/SKILL.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/using-skill-engine/SKILL.md#L98-L118)) This reference walks the command surface for setup, routing, review, and housekeeping; the crawl mechanics of `discover`/`refresh` live in the discover-refresh reference and the `self-audit` drift checks in the evaluation-and-audit reference.

The spine of the whole surface is the staging model: `discover`, `refresh`, and `new-reference` never touch the live contextualizer — they write a proposal into a sibling `<name>-context.proposed/` directory, and that proposal reaches the live tree only through `review` then `apply`, with `discard` as the exit hatch. Two commands sit outside the staging model: `engine-bootstrap` writes straight to the live tree (there is nothing to review on a first scaffold), and `clean-cache`/`config-set` touch the clone cache and plugin config rather than any contextualizer. ([`engine-bootstrap/references/stamping-and-templates.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/engine-bootstrap/references/stamping-and-templates.md#L7-L16), [`apply/SKILL.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/apply/SKILL.md#L6-L8))

## Where each command writes

| Command | Writes to | Key gate / precondition |
|---|---|---|
| `using-skill-engine` | nothing (router) | inspects install state, then dispatches |
| `engine-bootstrap` | live tree, directly | no existing `*-context/` (else pauses to confirm) |
| `discover` / `refresh` | staged `.proposed/` | no pending proposal already staged |
| `new-reference` | staged `.proposed/` | halts if a proposal is already staged |
| `review` | staged `.proposed/` only | manifest present; mutates REVIEW.md Step 2 in place |
| `apply` | promotes `.proposed/` to live | review actually ran + exactly one Step 3 tick |
| `discard` | removes `.proposed/` | one-shot `y` confirmation |
| `status` | nothing (read-only) | — |
| `clean-cache` | `~/.cache/skill-engine/` | dry-run first, then literal `yes` |
| `config-set` | `$CLAUDE_PLUGIN_DATA/config.json` | `$CLAUDE_PLUGIN_DATA` set |

## using-skill-engine — the router

`using-skill-engine` is the entry point when the user names the engine but not a workflow. It searches all three install levels for a `*-context/` root, reads `research/.research-state.json` as the installed-marker, and dispatches: no root routes to `engine-bootstrap`; a corrupt marker routes to `engine-bootstrap` behind its confirm guard; multiple roots ask which one; a healthy install routes to the named maintenance workflow, or renders the menu when none was named. ([`using-skill-engine/SKILL.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/using-skill-engine/SKILL.md#L79-L121)) A pending-proposal pre-step runs before any dispatch: if a `*-context.proposed/` exists and the requested workflow mutates (`discover`/`refresh`/`new-reference`), the router refuses and points at `review`/`apply`/`discard`; the read-only `status`/`self-audit` and the live-writing `engine-bootstrap` are exempt. ([`using-skill-engine/SKILL.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/using-skill-engine/SKILL.md#L33-L73))

## engine-bootstrap — scaffold to live

`engine-bootstrap` takes one or more source URLs or local paths and scaffolds a contextualizer under `.claude/skills/<slug>-context/`. Intake asks exactly one content question (the URLs/paths) and zero engine-taxonomy questions; `id` (a kebab-case slug), `kind` (inferred from the URL shape), and topology (from the source count) are all auto-detected, and monorepo membership is explicitly deferred to DISCOVER rather than probed here. ([`engine-bootstrap/references/intake-and-detection.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/engine-bootstrap/references/intake-and-detection.md#L44-L47), [`engine-bootstrap/references/intake-and-detection.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/engine-bootstrap/references/intake-and-detection.md#L154-L178))

Registering tens of sources is what the flags are for, because the per-source prompts are what scale badly. `--sources-file <path>` reads one source per line from a plain-text file and combines those entries with any positional arguments; `--branch-default-all` suppresses Step 2.4's per-source branch prompt, recording every unanswered git-managed source at its default branch; `--clone-all` and `--clone-none`, mutually exclusive, answer Step 3.5's cache-seed consent for every git-managed source at once rather than one `[y/N]` at a time; and `--probe` adds an opt-in reachability pass at intake that collects every unreachable URL into one table behind one confirmation, before anything is stamped — a source it flags unreachable is skipped by the seed even under `--clone-all`. ([`engine-bootstrap/references/intake-and-detection.md` § Batch intake](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/engine-bootstrap/references/intake-and-detection.md#L88-L152), [`intake-and-detection.md` § --branch-default-all](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/engine-bootstrap/references/intake-and-detection.md#L212-L232), [`intake-and-detection.md` § Reachability probe](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/engine-bootstrap/references/intake-and-detection.md#L301-L368), [`engine-bootstrap/references/cache-seeding.md` § Step 3.5](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/engine-bootstrap/references/cache-seeding.md#L5-L18))

Unlike the staged workflows, bootstrap stamps templates straight into the live tree because there is no pre-existing tree to diff against; its only network act is an optional, consented cache seed (`git clone` into `~/.cache/skill-engine/git-managed/`), and it exits recommending `discover`. ([`engine-bootstrap/references/stamping-and-templates.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/engine-bootstrap/references/stamping-and-templates.md#L7-L16), [`engine-bootstrap/references/cache-seeding.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/engine-bootstrap/references/cache-seeding.md#L5-L18))

## review — predict-then-compare

`review <name>` inspects a staged proposal without mutating it or the live tree, and runs in two passes. The first pass prints the manifest summary (added / modified / removed buckets), the configured diff command, and the path to `.review/REVIEW.md` for the user to fill Step 1. ([`review/SKILL.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/review/SKILL.md#L22-L58)) The second pass is the load-bearing predict-then-compare step: after the user records their predictions in Step 1, re-running `review` computes 5-9 disagreements between those predictions and the proposal's actual coverage — scope mismatches ranked highest — and writes them into Step 2 in place, leaving Steps 1 and 3 byte-for-byte untouched. This is the surface that teaches the engine what "good" means for the source; it is not a rubber stamp. ([`review/SKILL.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/review/SKILL.md#L60-L82), [`review/SKILL.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/review/SKILL.md#L6-L8))

## apply — promotion and the gate

`apply <name>` promotes the proposal to the live tree one atomic-rename per manifest entry, and preserves `REVIEW.md` plus the manifest as an audit trail in the live `.review/`. ([`apply/SKILL.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/apply/SKILL.md#L6-L8), [`apply/references/promotion-and-reconciliation.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/apply/references/promotion-and-reconciliation.md#L5-L34)) The apply gate is the spine of the whole surface: apply blocks unless the review actually ran. A ticked Step-3 box alone does not prove the predict-then-compare pass happened, so apply runs two literal-content checks — Step 1 predictions must no longer contain the `___` blanks, and Step 2 must no longer hold its unpopulated `(Run /skill-engine:review …)` placeholder — and if either fails it halts without mutating either tree and tells the user to run `review` first. ([`apply/references/pre-promotion-gates.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/apply/references/pre-promotion-gates.md#L13-L24)) Three further gates guard promotion: exactly one Step 3 box ticked, that box must not be `reject`, and the live tree must be unchanged since staging (each entry's live hash is compared against the manifest's `sha_before`). On success apply writes a `research/review-state.json` sign-off ledger and reconciles the provisional-preamble banner in the live `SKILL.md`. ([`apply/references/pre-promotion-gates.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/apply/references/pre-promotion-gates.md#L26-L50), [`apply/references/promotion-and-reconciliation.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/apply/references/promotion-and-reconciliation.md#L48-L105))

## discard — drop a proposal

`discard <name>` removes the `.proposed/` staging directory (and its `.review/` audit trail) with a single `rm -rf` after a one-shot `y` confirmation; the live contextualizer is never touched. It is idempotent — discarding a non-existent proposal exits zero — and is the documented exit when `review` surfaces too much divergence or when the user ticked `[x] reject`, which `apply` refuses to promote. ([`discard/SKILL.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/discard/SKILL.md#L6-L12), [`discard/SKILL.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/discard/SKILL.md#L34-L56))

## status — freshness and pending review

`status [name]` is a read-only dashboard: it lists fresh / stale / critical references by age, surfaces any pending `.proposed/` proposal and how far its review has progressed (awaiting Step 1, Step 2 not generated, signed off, or not yet signed off), lists the local clone cache on disk, groups any `slice_of` source beneath its parent — the parent's row first, then each slice by its own `slice_id` and its own freshness — and renders each in-scope source's `importance` alongside the root `probe_budget` — with a worst-case line naming how many sources' re-read the budget would skip at the next refresh, and the reminder that all of them are probed either way. It never writes, fetches upstream, or advances a proposal — a safe first step when returning to a contextualizer after a gap. ([`status/SKILL.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/status/SKILL.md#L6-L11), [`status/SKILL.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/status/SKILL.md#L42-L80), [`status/SKILL.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/status/SKILL.md#L264-L270))

## new-reference — one reference, staged

`new-reference` registers a single new reference when a topic is known ahead of time and a full DISCOVER pass would be overkill. It stages — never writing to the live tree — a new `references/<source-slug>-<topic>.md` (manifest `added`) plus a copy-on-write catalog row in `SKILL.md` (`modified`), registering any as-yet-unregistered source in `source-paths.json` as part of the same proposal; everything lands live only through `apply`. It halts if a proposal is already staged, and runs the same pre-stage validation (catalog bijection, no-frontmatter, `verify.sh`) as DISCOVER against an ephemeral merged view. ([`new-reference/SKILL.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/new-reference/SKILL.md#L6-L26), [`new-reference/SKILL.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/new-reference/SKILL.md#L87-L92), [`new-reference/SKILL.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/new-reference/SKILL.md#L109-L132))

## clean-cache and config-set — housekeeping

`clean-cache [kind]` is the opt-in destructive path for the persistent clone cache under `~/.cache/skill-engine/`; it always dry-runs first, listing every directory in scope with sizes, and deletes only after the user replies with the literal word `yes`. It touches no contextualizer state, only the regenerable cache. ([`clean-cache/SKILL.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/clean-cache/SKILL.md#L6-L8), [`clean-cache/SKILL.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/clean-cache/SKILL.md#L55-L97), [`clean-cache/SKILL.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/clean-cache/SKILL.md#L174-L181)) `config-set <key> "<value>"` persists an engine-wide config value into `$CLAUDE_PLUGIN_DATA/config.json`; the one key the engine reads today is `diff.tool`, the command `review` prints for inspecting a proposal (default `git diff --no-index --color`). It fails loudly when `$CLAUDE_PLUGIN_DATA` is unset rather than writing a fallback the readers would never find. ([`config-set/SKILL.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/config-set/SKILL.md#L6-L8), [`config-set/SKILL.md`](https://github.com/nick-railsback/skill-engine/blob/89bb5fa74f9b576adad6c0ed3d99211a48b4ab29/plugin/skill-engine/skills/config-set/SKILL.md#L24-L34))
